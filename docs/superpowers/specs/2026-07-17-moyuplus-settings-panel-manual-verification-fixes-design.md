# MoyuPlus 设置面板人工验收修订设计

**日期：** 2026-07-17  
**状态：** 已实施并通过自动验收及真实 Extension Development Host 人工验收（2026-07-17）
**关联设计：** `2026-07-16-moyuplus-unified-settings-panel-design.md`

## 1. 背景

统一设置面板在真实 Extension Development Host 人工验收中发现四项问题：入口位置不符合常用操作路径；快捷键列表展示的是静态默认绑定而非用户实际生效绑定；阅读设置滑块保存时整页重绘导致页面向上跳动；阅读背景颜色未应用，且默认值不应固定为白色。

本修订替代关联设计中与入口、快捷键绑定展示、范围控件渲染和阅读颜色默认语义冲突的部分。其余安全、串行保存、全局作用域、响应关联和可访问性要求保持不变。

## 2. 编辑器右键入口

- `MoyuPlus Settings` 从 `explorer/context` 移到 `editor/context`。
- 入口显示在代码编辑器区域的右键菜单中；不增加只读、差异编辑器或语言类型限制。命令仍忽略上下文参数，只打开单例设置面板。
- 命令面板、Reader 设置按钮和 Git Log 设置按钮入口保持不变。
- 自动测试同时断言存在 `editor/context` 贡献且不再存在对应的 `explorer/context` 贡献。

## 3. 快捷键分区

VS Code 扩展公共 API 不提供可靠的“最终生效快捷键”查询能力。用户绑定、移除、冲突、平台差异和 `when` 条件都会使静态默认值与实际状态不一致，因此设置面板不再回显任何按键值。

- 保留动作名称、用途说明、实验性标记和风险说明。
- 移除快捷键值徽标以及“未设置默认快捷键”等推断性文案。
- 不读取或解析用户 `keybindings.json`，不依赖 VS Code 内部命令或本地文件布局。
- 保留“在键盘快捷方式中配置 MoyuPlus”按钮；原生 Keyboard Shortcuts 页面继续负责展示实际绑定、冲突和删除操作。

## 4. 范围控件稳定渲染

当前范围控件在本地提交和宿主响应时调用全量 `render()`，通过 `replaceChildren()` 重建页面。重建会改变滚动位置，并在拖动期间替换活动控件。

修订后的范围控件采用原地同步：

1. `input` 事件只更新现有 `<output>` 和 Webview 本地预览，并重置 250 ms 防抖计时器。
2. `change` 事件先取消对应防抖计时器，再提交尚未提交的最终值；防抖与 `change` 对同一个最终值最多产生一次保存请求和一次 live region 播报。
3. 提交时更新 reducer 状态并发送保存请求，但不重建设置页面。
4. 保存中、成功和失败状态直接同步到现有状态区域。
5. 对范围控件的最新保存响应，直接同步权威值、禁用状态和错误状态；失败时只原地回滚该控件。
6. 分区切换、恢复默认、实例切换和 dispose 必须取消尚未触发的范围计时器，禁止遗留计时器发送陈旧请求。

范围控件分别跟踪“用户交互仍在进行”和“最新保存仍在等待”两种状态：

- 指针交互从 `pointerdown` 开始，到 `pointerup` 或 `pointercancel` 结束。
- 键盘调整从相关 `keydown` 开始，到对应 `keyup` 或控件失焦结束。
- 没有可识别的指针或键盘起点时，首个 `input` 开始交互，并由 `change` 或失焦结束。
- 保存等待状态从请求发出开始，到该控件最新请求成功、失败或被更新请求取代后结束。

任一状态仍存在时均视为活动范围会话。只有用户交互已经结束、对应防抖计时器已经清理且最新保存也已结束，才允许结束会话。活动会话期间禁止通过 `replaceChildren()` 或等价操作替换该滑块节点：

- 外部 configuration 刷新、可见性快照和其他全量状态仍按面板串行队列更新 reducer 中的权威状态，但其结构性完整渲染延后并合并。
- 与当前滑块或保存状态有关的变化原地同步；其他分区状态可等到活动会话结束后一次性渲染。
- 活动会话结束后执行至多一次延后渲染，并显式保持滚动位置；若控件仍应存在，则保持其焦点。

该设计保证滑块节点、焦点和页面滚动位置在一次拖动及其保存响应期间保持稳定。迟到响应与陈旧 `stateVersion` 的拒绝规则保持不变。

## 5. 阅读颜色语义

### 5.1 默认状态

定义 `ReaderColor = 'theme' | HexColor`，其中 `HexColor` 是规范化的小写六位十六进制颜色 `#[0-9a-f]{6}`。阅读文字颜色与背景颜色默认均为字面量 `theme`，不再以 `#1f2328` 或 `#ffffff` 表示默认状态。

- 当主题为“跟随 VS Code”时，Reader 使用 `--vscode-editor-foreground` 与 `--vscode-editor-background`。
- 当主题为明亮、纸张或深色时，主题继承值使用该阅读主题已有的前景色和背景色。
- 主题切换后，处于主题继承状态的颜色随主题更新。

### 5.2 自定义颜色

- 用户通过颜色选择器或合法的六位十六进制文本设置颜色后，该项转为自定义颜色并覆盖主题颜色。
- 颜色控件必须用文字标明当前是“跟随主题”还是自定义十六进制值。
- 提供将单个颜色恢复为“跟随主题”的操作；“恢复阅读默认值”同时将两个颜色恢复为主题继承。
- `applyReaderPreferences` 对主题继承值移除对应内联颜色，使 CSS 主题规则生效；对自定义值写入 `color` 或 `backgroundColor` 内联样式。

### 5.3 兼容性

- 保持现有 ReaderPreferences 持久化键不变。
- 默认对象、恢复默认、设置快照和持久化对象均使用字面量 `theme` 表示继承；颜色控件用文字“跟随主题”表达该值，不把派生出的当前主题色伪装成已保存十六进制值。
- Webview 保存消息只接受 `theme` 或六位 `HexColor`。持久化回读为兼容既有数据继续接受 `#RGB`，但立即规范化为小写 `#RRGGBB`；其他值回退为 `theme`。
- 已持久化的合法十六进制颜色继续作为用户自定义颜色使用，不擅自迁移或覆盖。
- 颜色消息值域和默认快照结构发生变化，因此 `SETTINGS_PROTOCOL_VERSION` 从 1 升为 2；版本不匹配时继续使用基线定义的阻断错误流程。

## 6. 测试策略

实施遵循 RED → GREEN → REFACTOR，每项先增加可观察失败的回归测试：

- package contribution：设置入口仅贡献到 `editor/context`。
- 快捷键模型与 Webview：动作列表不包含或渲染任何绑定值徽标。
- 范围控件：输入、提交及保存响应不替换活动滑块节点，滚动位置与焦点保持稳定；失败响应原地回滚；`change` 与防抖不会重复提交。
- 范围控件竞态：拖动期间到达外部 configuration 刷新或全量快照时不替换活动节点，会话结束后只执行一次合并渲染；按住滑块停顿至防抖保存完成后继续拖动，活动节点仍不被替换。
- 阅读偏好：默认颜色为主题继承值，合法旧十六进制值保持不变，非法值回退为主题继承。
- 阅读样式：主题继承时清除内联前景/背景色，自定义颜色时正确写入，两者更新后均立即重新排版。
- 完整门禁：`npm run compile`、`npm run test:unit`、`npm run test:layout`、`git diff --check`。

## 7. 人工验收补充

1. 在代码编辑器正文区域右键可见 `MoyuPlus Settings`；资源管理器右键不再显示该入口。
2. 快捷键分区不显示任何推断的按键值；点击按钮后由 VS Code 原生页面显示实际绑定。
3. 将阅读设置页面滚动到中下部并持续拖动任一滑块，页面不跳动，滑块不中断，保存状态正常更新。
4. 初次打开时背景颜色显示“跟随主题”，切换 VS Code 明暗主题后 Reader 背景同步变化。
5. 选择自定义背景色后 Reader 立即生效；恢复“跟随主题”后重新使用当前主题背景。
