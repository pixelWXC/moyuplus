# 打字练习 IME 候选过滤修复设计

日期：2026-07-28

## 背景

`committedBatch` 当前把“文档内容连续 1.5 秒没有变化”当成输入法已经提交候选。人工验收发现，第三方中文输入法可以让候选保持选中超过 1.5 秒而仍处于预编辑状态。定时器随后把预编辑文本送入输入判定；文本不是目标句的合法前缀时，生命周期适配器执行回滚，人工 Extension Host 测试因此失败并退出。

VS Code 公共 `TextDocumentChangeEvent` 不暴露 IME composition 生命周期，所以仅靠静默时长不能准确识别提交边界。

## 目标

- 候选列表打开、切换候选或候选保持选中期间，只要文档仍是与当前目标不一致的预编辑批次，就不推进练习、不记录输入尝试、不回滚、不退出。
- 候选真正上屏且形成目标文本的合法后续前缀后，只提交最终稳定文本一次。
- 保留锚点破坏、多光标、跨活动行编辑等结构保护。
- 不依赖 VS Code 未公开的 `compositionStart`、`compositionEnd` 等内部命令。

## 非目标

- 不重写练习编辑器为 Webview 或 Custom Editor。
- 不改变逐字判定模式。
- 不调整候选稳定窗口的具体时长；本次修复改变的是窗口结束后的判定语义。
- 不把输入法厂商特有事件或私有 API 引入领域层。

## 方案

### 1. 区分结构错误与未确认批次

`DocumentChangeAdapter` 继续负责纯文档结构分类：

- 锚点无效、多光标、跨行或非受控区域编辑仍返回 `rollback`。
- 当前活动行尾部相对检查点增长仍返回 `input`。

稳定窗口结束后，`PracticeDocumentLifecycleAdapter` 不再直接把所有 `input` 发送到 `PracticeApplicationCoordinator.input`。它先请求一个只读的 committed-batch 确认端口判断该批次是否为当前目标的合法后续。此端口按可观察文档内容分类，不声称识别 VS Code 未公开的 composition 状态。

- `confirmed`：stage 文档并执行一次 input。
- `provisional`：丢弃本次定时结算，不 stage、不 input、不 rollback；后续文档变化重新建立稳定窗口。

### 2. 只读确认端口

应用层新增窄接口，只回答“这段 committed-batch 文本能否从当前 session 的 targetIndex 合法推进”，不写 Session、Store、Checkpoint 或 Result。

确认逻辑复用 Session Engine 的字素分割和 TextPolicy 归一化语义，包括：

- Unicode 字素；
- 中文标点等价；
- 大小写策略；
- 空白处理；
- 自动跳过的结构目标。

确认过程必须是 O(本次批次长度)，不得复制完整输入历史。

为避免改变逐字模式，生命周期适配器只在 `evaluationMode === 'committedBatch'` 时调用该端口。

### 3. 错误语义

在稳定上屏模式中，未确认批次保持为可编辑的预编辑/候选文本，不进入成绩事实，也不触发 `blockedOnError`。用户修正或最终提交正确候选后，再由新的稳定文档变化推进。

真正结构错误仍立即回滚。应用或存储异常仍按原路径回滚并向上报告，不能被误当作 IME 临时态吞掉。

### 4. 人工冒烟入口

人工 IME harness 使用与正式装配相同的确认边界。它不再依赖 `input` 回调抛出“不是目标句前缀”来识别候选临时态；临时态应在进入 input 之前被过滤。

现有 1.5 秒仅用于等待文档变化稳定，不再宣称等价于候选已提交。

## 测试

按 TDD 顺序增加以下证据：

1. 生命周期单测：候选仍处预编辑状态、文档内容不是合法目标后续并保持超过稳定窗口时，结果为 provisional；`stage`、`input`、`rollback` 均不调用。
2. 生命周期单测：候选经历多个非目标预编辑批次后最终形成确认文本，只提交最后文本一次。
3. 生命周期单测：锚点破坏、多光标和跨行编辑仍回滚。
4. 应用/领域单测：只读确认遵守字素、标点、大小写和空白策略，且不改变 Session。
5. Registration/组合测试：正式 Workspace 工厂把确认端口接入 lifecycle。
6. Extension Host 人工验收：本次输入法暴露非目标预编辑文本时，候选保持选中超过 1.5 秒不退出；提交形成合法目标后续后进度才推进，完整目标最终通过。

## 风险与约束

- 公共 VS Code API 无法证明某段文本已结束 composition。本方案把“与当前目标不一致的稳定批次”保守地视为 provisional，因此 committed-batch 模式中的错误批次不会立即计为错误；用户需先把文本修正为合法目标后续。逐字模式的错误统计不受影响。
- 如果某输入法在 composition 尚未结束时就把预编辑内容暴露为与最终提交完全相同的合法目标后续，扩展无法仅凭公共文档事件识别这一状态，本方案可能提前推进。该限制不阻塞本次复现：当前失败路径已经进入“不是目标句前缀”后的回滚。
- 确认端口必须保持只读，否则“先确认再提交”会产生双写或重复 InputAttempt。
- 过滤只适用于内容语义；任何结构越界都不能降级为 provisional。

## 验收标准

- 本次复现步骤“输入世界但不提交，切换候选并让正确候选保持选中超过 1.5 秒”不再退出。
- 在本次待验收输入法暴露的非目标预编辑文本期间，进度不变化。
- 最终提交“世界”后只增加对应字素数，没有拼音、临时候选或重复尝试。
- 现有单元测试、TypeScript 编译和 Extension Host 自动测试通过。
- `docs/typing-practice-verification.md` 的 M1 人工验收最终通过。
